## 2. Fixes Applied

All fixes live in `InkPilot/InkPilot.xcodeproj/project.pbxproj`. No source files, asset catalog contents, Info.plist, or entitlements were touched.

### 2.1 `Resources` group relocated under `InkPilot/`

The `Resources` PBXGroup was originally a child of the project root group, which made `Assets.xcassets`, `Info.plist`, and the `.strings` files resolve to `InkPilot/Resources/...` (one directory level too shallow). The actual on-disk location is `InkPilot/InkPilot/Resources/...`. `actool` reported:

```
error: None of the input catalogs contained a matching … app icon set … named "AppIcon".
warning: Failed to read file attributes for "/…/InkPilot/Resources/Assets.xcassets"
```

Fix: move the `Resources` group from the `Root` group into the `InkPilot` group (which has `path = InkPilot`). After the move, paths resolve correctly and both `AppIcon` and `AccentColor` are picked up by the asset catalog compiler.

### 2.2 `Localizable.strings` files added to the target

`en.lproj/Localizable.strings` and `zh-Hans.lproj/Localizable.strings` had `PBXFileReference` entries but were **not** in the `PBXResourcesBuildPhase`. As a result, no `.lproj/` directory ended up in the built `.app`, and every `String(localized:)` call silently fell back to the key.

Fix: add two `PBXBuildFile` entries and append them to the resources build phase.

Verification after fix (via `find` on the built bundle):

```

…/InkPilot.app/zh-Hans.lproj/Localizable.strings
```

Runtime check (default simulator locale, zh-Hans): HomeView shows `InkPilot` / `用笔思考，让 AI 续航灵感。` / `让 AI 续航你的下一个灵感。` / `新建 AI 画布`.

Runtime check after `defaults write -g AppleLanguages -array en`: HomeView title `InkPilot` and the same English strings; CanvasView shows `AI Pilot / 3 suggestions`, `Ask AI about this canvas…`.

## 4. Architectural Notes (for future maintainers)

- **`MockSuggestionService` is behind the `SuggestionService` protocol** (`AI/SuggestionService.swift`). Swap by changing the default argument of `CanvasViewModel.init`.
- **`CanvasContextBuilder` is a stub** that returns an empty `CanvasContext` — wire in `InkSnapshotRenderer` + `VisionOCRService` here when real recognition is needed.
- **All UI strings go through `String(localized:)`** — no hard-coded copy. See `Resources/en.lproj/Localizable.strings` for the key list.
- **State container pattern**: `CanvasViewModel` is `@Observable`; views bind via `let viewModel: CanvasViewModel` (passed down from `CanvasView`).
- **File size budget**: every Swift file is under 110 lines (CLAUDE.md cap is 300). 25 Swift files total.

## 5. How to Reproduce

From the repo root:

```sh
git checkout v0.1-candidate-1
cd InkPilot
xcodebuild \
  -project InkPilot.xcodeproj \
  -scheme InkPilot \
  -destination 'platform=iOS Simulator,name=iPad Pro 13-inch (M5)' \
  -configuration Debug build
```

Boot the simulator, install, launch, and confirm:

1. App opens to the brand hero card (HomeView).
2. Tap **New AI Canvas** → CanvasView with floating toolbar, PencilKit canvas, AI Pilot panel, and prompt capsule.
3. Switch simulator language to verify localization.

## 6. Known Limitations (pre-existing, out of scope for V0.1)

- Ghost suggestion appears at a fixed location; not yet anchored to ink coordinates.
- No persistence — accepted cards and drawings vanish on app relaunch.
- AppIcon is declared in `Assets.xcassets` but no image assets are present yet; the app will ship without an icon. This does not block V0.1 (the asset catalog still validates and produces an empty icon set).

These are intentionally deferred to post-V0.1 polish.
